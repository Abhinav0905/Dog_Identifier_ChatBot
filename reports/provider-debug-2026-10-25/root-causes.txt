ASK DORJEE: WHY THE INDORE / KOCHI LOOKUPS FAILED

This audit used current code, current EC2 logs, captured synthetic lookup stages and actual browser replies. It did not use old project memory.

1. Neighbourhood incorrectly became a hard provider boundary.
   The actual Indore request stored requested_location_text="Vijay Nagar, Indore" and resolved city Indore. The reviewer required the first comma-separated component, Vijay Nagar, in each provider passage. Valid clinics elsewhere in Indore were discarded. _discovery_locality now accepts the validated city when that city was explicitly included after the neighbourhood. Exact towns such as Mhow and explicitly selected institutions remain constrained. This is a generic rule, not an Indore provider list.
   Files: app.py; services/web_search.py; services/search_evidence.py.

2. First aid was promised separately but not delivered for a deep wound.
   The research prompt intentionally delegated immediate first aid to application code. The emergency detector recognized bleeding/collapse/vehicle trauma but missed deep or open wounds. It also handled search outages differently from unconfirmed contact results. Deep/open wound guidance is now recognized and retained through all lookup outcomes, while phone-only requests retain their output constraint.
   Files: services/triage.py; app.py.

3. Useful first-party evidence was treated as conflicting-provider content.
   "Mobile Veterinary Clinic", ordinary service prose and "Contact Branches" caused a publisher page to be rejected. Captured Kochi evidence already described a real pet hospital, address and service. The checker now distinguishes generic services and a provider's own branches from another named institution. Competing providers and unrelated campuses still fail validation. Branch phone association is kept with the displayed address.
   File: services/search_evidence.py.

4. Evidence review used a short routing timeout.
   Logs showed an APITimeoutError during the original Kochi evidence review. Review now has a separate 20-second cap and GPT-5.6 reasoning=none, still clamped by the shared turn deadline. The bounded research budget allows a repair pass. This does not make unreadable websites accessible or certify admission.
   Files: config.py; services/search_evidence.py.

5. Concurrent lookups discarded source URLs after 250 milliseconds.
   EC2 logs showed a burst of verification concurrency-limit messages and zero readable pages for one request while another occupied all four fetch slots. Fetches now queue within their existing deadline. The four-slot limit and network/SSRF protections remain. A regression test releases a busy slot after 350 ms and confirms the source is still read.
   File: services/web_search.py.

6. Institution-preservation rules over-constrained open discovery.
   The old refinement instruction prohibited substituting organisations even when no institution had been requested. It now locks an explicitly selected institution, while open discovery can replace weak leads with better-supported clinics in the explicitly requested city. Research includes pet and small-animal clinics without requiring NGO, free-care or street-dog wording. Original prompt text is archived; Deb's full reference and shared cultural policy are unchanged.
   Files: prompts/runtime-v2/03_web_search_system_template_english.txt; 04_contact_evidence_review_system.txt; support/web_refinement.txt.
